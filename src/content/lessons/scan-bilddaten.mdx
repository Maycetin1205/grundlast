# Scan- & Bilddaten rechnen

## Worum geht's

Du lernst, wie groß eine Bilddatei oder ein Scan wirklich ist — und wie du das ausrechnest.
Das ist eine klassische Prüfungs-Rechenaufgabe: DIN-A4-Dokument scannen, Speicherbedarf für ein
ganzes Jahr berechnen. Schritt für Schritt, Formel für Formel.

---

## Erklärung

### Die vier Bausteine

Um die Dateigröße eines Scans oder Bildes zu berechnen, brauchst du vier Dinge:

**1. Maße in Pixel umrechnen**

Ein Scanner arbeitet mit **DPI** (Dots Per Inch = Punkte pro Zoll). Zoll (Inch) ist eine
andere Längeneinheit:

```
1 Inch = 2,54 cm
→ cm in Inch umrechnen: Inch = cm / 2,54
```

Dann:
```
Breite in Pixel = Breite_in_Inch × DPI
Höhe in Pixel  = Höhe_in_Inch  × DPI
```

**2. Pixelanzahl berechnen**

```
Pixelanzahl = Breite_px × Höhe_px
```

**3. Bits berechnen**

Die **Farbtiefe** gibt an, wie viele Bits pro Pixel gespeichert werden.

| Farbtiefe | Bedeutung | Bits pro Pixel |
|---|---|---|
| 1 Bit | Schwarz-Weiß | 1 |
| 8 Bit | Graustufen (256 Grautöne) | 8 |
| 24 Bit | RGB-Farbe (16,7 Mio. Farben) | 24 |
| 32 Bit | RGB + Transparenz (RGBA) | 32 |

```
Bits gesamt = Pixelanzahl × Farbtiefe (in Bit)
```

**4. Bytes und Einheiten**

```
Bytes = Bits / 8

Dann weiter umrechnen (Binärpräfixe!):
KiB = Bytes / 1.024
MiB = Bytes / 1.024²  = Bytes / 1.048.576
GiB = Bytes / 1.024³  = Bytes / 1.073.741.824
TiB = Bytes / 1.024⁴  = Bytes / 1.099.511.627.776
```

> **Wichtig:** In Aufgaben steht fast immer TiB, GiB oder MiB — also Binärpräfixe
> (Teiler = Potenzen von 1.024), nicht SI-Präfixe (Teiler = Potenzen von 1.000).

**Komprimierung**

Wenn die Aufgabe eine Komprimierung angibt (z. B. „auf 50 % komprimiert"), dann:
```
Komprimierte Größe = Ursprungsgröße × Komprimierungsfaktor
z. B. auf 50 % → × 0,5
```

## Beispiele

**Beispiel 1: DIN-A4-Scan – Jahresspeicherbedarf**

**1. Aufgabe und gegebene Werte**

```
Format: DIN A4 = 29,7 cm × 21,0 cm
Auflösung: 200 DPI
Farbtiefe: 24 Bit
Komprimierung: auf 50 %
Dokumente/Tag: 1.800
Arbeitstage/Jahr: 250
```

Typische IHK-Aufgabe: Ein Unternehmen scannt täglich Dokumente. Wie viel Speicher braucht es pro Jahr?

**2. cm → Inch umrechnen**

```
Breite: 29,7 cm / 2,54 ≈ 11,69 Inch
Höhe:  21,0 cm / 2,54 ≈  8,27 Inch
```

DPI-Angaben beziehen sich auf Inch. Zürst müssen die Maße von Zentimetern in Inch umgerechnet werden.

**3. Pixel berechnen**

```
Breite: 11,69 × 200 ≈ 2.338 px
Höhe:   8,27 × 200 ≈ 1.654 px

Pixelanzahl = 2.338 × 1.654 = 3.867.052 px
```

Inch × DPI ergibt die Pixel in einer Richtung. Breite × Höhe ergibt die Gesamtpixelzahl.

**4. Bits berechnen**

```
Bits = 3.867.052 × 24 = 92.809.248 Bit
```

Jeder Pixel braucht 24 Bit (RGB-Farbe). Pixelanzahl × Farbtiefe = Bits gesamt.

**5. Bytes berechnen**

```
Bytes = 92.809.248 / 8 = 11.601.156 Bytes
```

1 Byte = 8 Bit. Division durch 8 ergibt die Größe in Bytes.

**6. Komprimierung anwenden**

```
Komprimiert = 11.601.156 × 0,5 = 5.800.578 Bytes
```

Auf 50 % komprimiert bedeutet: die Hälfte der Originalgröße bleibt übrig. Deshalb × 0,5.

**7. Scans pro Jahr**

```
Scans/Jahr = 1.800 × 250 = 450.000 Scans
```

Tägliche Menge × Arbeitstage ergibt die Jahresanzahl.

**8. Gesamtspeicher in TiB**

```
Gesamt = 5.800.578 × 450.000 = 2.610.260.100.000 Bytes

TiB = 2.610.260.100.000 / 1.099.511.627.776
    ≈ 2,37 TiB
```

Bytes pro Scan × Anzahl Scans = Gesamtbytes. Dann durch 2^40 (= 1.099.511.627.776) für TiB. Ergebnis: ca. 2,37 TiB pro Jahr.

**Beispiel 2: Einzelbild – Dateigröße in MiB**

**1. Aufgabe**

```
Bild: 1.000 × 1.000 Pixel
Farbtiefe: 24 Bit
Gesucht: Dateigröße in MiB (unkomprimiert)
```

Einfachere Variante: Pixelzahl ist direkt gegeben, kein Inch-Umrechnen nötig.

**2. Bits berechnen**

```
Pixelanzahl = 1.000 × 1.000 = 1.000.000 px
Bits = 1.000.000 × 24 = 24.000.000 Bit
```

Breite × Höhe = Pixelanzahl. Dann × Farbtiefe.

**3. Bytes → MiB**

```
Bytes = 24.000.000 / 8 = 3.000.000 Bytes
MiB = 3.000.000 / 1.048.576 ≈ 2,86 MiB
```

3 Millionen Bytes durch 2^20 (= 1.048.576) ergibt ca. 2,86 MiB.

## Typische Fehler

- **cm ↔ Inch vergessen:** Die Aufgabe gibt Maße in cm an, DPI bezieht sich auf Inch.
  Ohne Umrechnung (÷ 2,54) kommen falsche Pixelzahlen raus.

- **24 Bit mit 24 Byte verwechseln:** Die Farbtiefe ist immer in **Bit**, nicht Byte.
  24 Bit = 3 Byte pro Pixel. In der Rechnung × 24 (Bit), dann am Ende ÷ 8 für Bytes.

- **Komprimierung falsch interpretiert:** „Auf 50 % komprimiert" heißt × 0,5 (die Hälfte
  bleibt übrig). NICHT: minus 50 Byte. NICHT: durch 50.

- **MiB vs. MB verwechseln:** In Aufgaben fast immer MiB/GiB/TiB gefragt (Binärpräfixe,
  Teiler 1.024). Mit 1.000 zu teilen (SI-Präfixe) gibt ein falsches Ergebnis.

- **DPI in beide Richtungen:** 200 DPI bedeutet 200 Punkte pro Inch in x-Richtung UND
  200 Punkte pro Inch in y-Richtung. Bei „200 × 200 DPI" gilt jeweils 200 für Breite und Höhe.
