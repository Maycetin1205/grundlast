# Normalisierung (1NF, 2NF, 3NF)

## Worum geht's

Du lernst, wie man fehlerhafte Datenbank-Tabellen Schritt für Schritt aufräumt — von
Datenbrei in klare, wartbare Strukturen. Die drei Normalformen 1NF, 2NF und 3NF sind
in der Prüfung wichtig: Du musst erkennen, welche Normalform verletzt ist, und
wissen, wie du sie herstellst.

---

## Erklärung

### Warum normalisieren?

Eine schlecht strukturierte Tabelle hat drei klassische Probleme:

| Problem | Beispiel |
|---|---|
| **Einfüge-Anomalie** | Ein neues Produkt kann nicht eingetragen werden, weil noch kein Kunde es bestellt hat |
| **Änderungs-Anomalie** | Eine Adresse steht in 50 Zeilen — beim Umzug müssen alle 50 geändert werden |
| **Lösch-Anomalie** | Der letzte Kunde löscht sich — dabei geht auch die einzige Produktinfo verloren |

Normalisierung löst diese Probleme, indem Daten aufgeteilt werden:
**Ein Fakt, ein Ort.**

### Die drei Normalformen

**1NF — Atomar:** Jede Zelle enthält genau einen Wert. Keine Listen, keine Mengen.

**2NF — Voll funktional abhängig:** Jede Nicht-Schlüssel-Spalte hängt vom **gesamten**
Primärschlüssel ab. Relevant nur bei zusammengesetztem Primärschlüssel.

**3NF — Keine transitiven Abhängigkeiten:** Kein Nicht-Schlüssel-Feld darf von einem
anderen Nicht-Schlüssel-Feld abhängen.

### Merksatz

> **1NF:** Keine Mehrfachwerte in einer Zelle.
> **2NF:** Alles hängt vom ganzen Schlüssel ab (nicht nur einem Teil).
> **3NF:** Nichts hängt von einem Nicht-Schlüssel ab.

## Beispiele – Schritt für Schritt

**1. Normalform herstellen**

**1. Ausgangstabelle prüfen (verletzt 1NF)**

```
Tabelle: Mitarbeiter
┌──────────────┬──────────────────────┐
│ Mitarbeiter  │ Skills               │
├──────────────┼──────────────────────┤
│ Max Müller   │ Java, C++, Python    │
│ Sara Koch    │ SQL, Excel           │
└──────────────┴──────────────────────┘
```

Problem: Die Spalte 'Skills' enthält mehrere Werte in einer Zelle (Liste). Das verletzt die 1NF — jede Zelle muss atomar (= unteilbar) sein.

**2. 1NF herstellen: Jeder Wert in eine eigene Zeile**

```
Tabelle: Mitarbeiter_Skills
┌──────────────┬────────┐
│ Mitarbeiter  │ Skill  │
├──────────────┼────────┤
│ Max Müller   │ Java   │
│ Max Müller   │ C++    │
│ Max Müller   │ Python │
│ Sara Koch    │ SQL    │
│ Sara Koch    │ Excel  │
└──────────────┴────────┘
```

Jetzt steht jeder Skill in einer eigenen Zeile. Die Tabelle ist in 1NF. Primärschlüssel wäre die Kombination (Mitarbeiter, Skill) — da beides zusammen eindeutig ist.

**2. Normalform herstellen**

**1. Ausgangstabelle prüfen (verletzt 2NF)**

```
Tabelle: Bestellung
Primärschlüssel: (BestellNr, ProduktNr) — zusammengesetzt!
┌──────────┬──────────┬───────────────┬──────────────┐
│BestellNr │ProduktNr │ ProduktName   │ KundenName   │
├──────────┼──────────┼───────────────┼──────────────┤
│ 1001     │ P01      │ Laptop        │ Max Müller   │
│ 1001     │ P02      │ Maus          │ Max Müller   │
│ 1002     │ P01      │ Laptop        │ Sara Koch    │
└──────────┴──────────┴───────────────┴──────────────┘
```

Problem: 'ProduktName' hängt nur von ProduktNr ab (nicht von BestellNr). 'KundenName' hängt nur von BestellNr ab (nicht von ProduktNr). Beide Spalten hängen nur von einem Teil des zusammengesetzten Schlüssels ab — 2NF verletzt!

**2. Abhängigkeiten analysieren**

```
BestellNr → KundenName (KundenName hängt NUR von BestellNr ab)
ProduktNr → ProduktName (ProduktName hängt NUR von ProduktNr ab)
(BestellNr, ProduktNr) → Menge (Menge hängt von BEIDEN ab ✓)
```

Wir prüfen für jede Spalte: Von welchem Teil des Schlüssels hängt sie ab? Spalten die nur von einem Teil abhängen, müssen ausgelagert werden.

**3. 2NF herstellen: Aufteilen in mehrere Tabellen**

```
Tabelle: Produkt
┌──────────┬───────────────┐
│ProduktNr │ ProduktName   │
├──────────┼───────────────┤
│ P01      │ Laptop        │
│ P02      │ Maus          │
└──────────┴───────────────┘

Tabelle: Bestellung
┌──────────┬──────────────┐
│BestellNr │ KundenName   │
├──────────┼──────────────┤
│ 1001     │ Max Müller   │
│ 1002     │ Sara Koch    │
└──────────┴──────────────┘

Tabelle: BestellPosition
┌──────────┬──────────┬───────┐
│BestellNr │ProduktNr │Menge  │
├──────────┼──────────┼───────┤
│ 1001     │ P01      │ 1     │
│ 1001     │ P02      │ 2     │
│ 1002     │ P01      │ 1     │
└──────────┴──────────┴───────┘
```

Jetzt hängt jede Spalte vom vollständigen Schlüssel ihrer Tabelle ab. Keine partielle Abhängigkeit mehr — 2NF erfüllt.

**3. Normalform herstellen**

**1. Ausgangstabelle prüfen (verletzt 3NF)**

```
Tabelle: Kunde
Primärschlüssel: KundenNr
┌──────────┬──────────────┬───────┬──────────────┐
│KundenNr  │ KundenName   │ PLZ   │ Ort          │
├──────────┼──────────────┼───────┼──────────────┤
│ K01      │ Max Müller   │ 80331 │ München      │
│ K02      │ Sara Koch    │ 80331 │ München      │
│ K03      │ Tom Braun    │ 10115 │ Berlin       │
└──────────┴──────────────┴───────┴──────────────┘
```

Problem: 'Ort' hängt von 'PLZ' ab — nicht direkt von 'KundenNr'. Das ist eine transitive Abhängigkeit: KundenNr → PLZ → Ort. Ändert sich der Ort einer PLZ, müssten alle Zeilen mit dieser PLZ geändert werden.

**2. Transitive Abhängigkeit erkennen**

```
KundenNr → PLZ (direkt ✓)
KundenNr → Ort (nur über PLZ, transitiv ✗)
PLZ → Ort (das ist das Problem)
```

Die Spalte 'Ort' hängt nicht direkt vom Primärschlüssel KundenNr ab, sondern vom Nicht-Schlüsselfeld PLZ. Diese transitive Kette muss aufgebrochen werden.

**3. 3NF herstellen: PLZ und Ort auslagern**

```
Tabelle: PLZ_Ort
┌───────┬──────────────┐
│ PLZ   │ Ort          │
├───────┼──────────────┤
│ 80331 │ München      │
│ 10115 │ Berlin       │
└───────┴──────────────┘

Tabelle: Kunde (bereinigt)
┌──────────┬──────────────┬───────┐
│KundenNr  │ KundenName   │ PLZ   │
├──────────┼──────────────┼───────┤
│ K01      │ Max Müller   │ 80331 │
│ K02      │ Sara Koch    │ 80331 │
│ K03      │ Tom Braun    │ 10115 │
└──────────┴──────────────┴───────┘
```

Jetzt hängt jede Spalte direkt vom Primärschlüssel ihrer Tabelle ab. Ändert sich der Ort der PLZ 80331, muss nur noch eine Zeile geändert werden. 3NF erfüllt.

---

## Typische Fehler

- **Mehrfachwerte in einer Zelle übersehen**: „Telefonnummer: 0171/123, 0172/456" —
  das ist bereits 1NF-Verletzung. Auch Komma-getrennte Listen in einer Zelle sind verboten.

- **2NF gilt nur bei zusammengesetztem Primärschlüssel**: Hat eine Tabelle einen
  einfachen Primärschlüssel (nur eine Spalte), ist sie automatisch in 2NF — dann
  gibt es keinen „Teil des Schlüssels", von dem etwas abhängen könnte.

- **PLZ → Ort ist das klassische 3NF-Beispiel**: Fast jede Aufgabe nutzt genau
  dieses Beispiel. PLZ bestimmt den Ort — beides muss in eine eigene Tabelle.

- **Normalform rückwärts bestimmen**: Wenn die Aufgabe fragt „Welche Normalform liegt vor?",
  prüfe in dieser Reihenfolge: Erst 1NF (Atomarität), dann 2NF (nur bei zusammengesetztem PK),
  dann 3NF (transitive Abhängigkeiten). Die höchste erfüllte Normalform ist die Antwort.
