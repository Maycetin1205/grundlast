# CPU, RAM und Massenspeicher

## Worum geht's

Wenn ein Arbeitsplatz-PC, Notebook oder kleiner Server ausgewählt wird, reichen
Produktnamen nicht. Du musst verstehen, welche Komponente welche Aufgabe hat:
<Term id="cpu">CPU</Term>, <Term id="ram">RAM</Term> und <Term id="massenspeicher">Massenspeicher</Term>
arbeiten zusammen, aber sie lösen unterschiedliche Probleme.

Dieses Kapitel baut die Hardware-Grundlage für LF2: Du kannst erklären, was ein
System schnell, reaktionsfähig, speicherstark oder passend für einen Kundenwunsch
macht.

## Was du danach kannst

Nach diesem Kapitel kannst du CPU, RAM, <Term id="ssd">SSD</Term> und <Term id="hdd">HDD</Term>
sicher unterscheiden. Du erkennst, warum <Term id="taktfrequenz">Taktfrequenz</Term>,
Kerne, <Term id="thread">Threads</Term>, <Term id="cache">Cache</Term>, RAM-Kapazität,
DDR-Generation, SATA und <Term id="nvme">NVMe</Term> nicht austauschbare Kennwerte
sind. Außerdem kannst du einfache Hardwareentscheidungen begründen, ohne dich von
einzelnen Zahlen oder Marketingnamen blenden zu lassen.

## Mentales Modell

Stell dir den Computer wie eine Werkstatt vor:

| Komponente | Werkstattbild | Aufgabe im Rechner |
|---|---|---|
| CPU | Fachkraft an der Werkbank | führt Befehle aus, rechnet, entscheidet |
| RAM | freie Arbeitsfläche | hält aktive Programme und Daten bereit |
| SSD/HDD | Regal und Archiv | speichert Programme, Dateien und Betriebssystem dauerhaft |
| Cache | kleine Ablage direkt neben der Hand | hält besonders oft benötigte Daten extrem nah an der CPU |

Wichtig ist das Zusammenspiel: Ein Programm liegt dauerhaft auf SSD oder HDD. Beim
Start wird es in den RAM geladen. Die CPU holt sich Befehle und Daten aus dem RAM,
nutzt Cache für häufig benötigte Teile und schreibt Ergebnisse wieder zurück.

## Der Faktenkern

| Komponente | Kernfrage | Schnell gemerkt | Typische Kennwerte |
|---|---|---|---|
| CPU | Wie schnell werden Befehle verarbeitet? | Rechen- und Steuerzentrale | Takt, Kerne, Threads, Cache, Leistungsaufnahme |
| RAM | Wie viel kann gleichzeitig aktiv bereitliegen? | schneller, flüchtiger Arbeitsspeicher | Kapazität, DDR-Generation, Datenrate, Kanäle |
| SSD/HDD | Wie viel bleibt dauerhaft gespeichert? | nichtflüchtiger Massenspeicher | Kapazität, Schnittstelle, Latenz, Durchsatz |
| Mainboard | Was passt physisch und elektrisch zusammen? | Verbindungs- und Kompatibilitätsbasis | CPU-Sockel, RAM-Slots, M.2, SATA, PCIe |

Merksatz: **CPU verarbeitet, RAM hält bereit, Massenspeicher bewahrt auf.**

## CPU: Befehle ausführen

Eine CPU führt Programmbefehle aus. Stark vereinfacht läuft immer wieder ein Zyklus:
Befehl holen, Befehl interpretieren, Befehl ausführen. Moderne Prozessoren machen das
hochoptimiert, parallel und mit mehreren Zwischenspeichern. Die CPU arbeitet dabei
eng mit RAM und Cache zusammen: RAM hält aktive Daten bereit, Cache hält besonders
häufig benötigte Daten noch näher an der CPU.

| Kennwert | Bedeutung | Worauf du achten musst |
|---|---|---|
| Taktfrequenz | Zyklen pro Sekunde, meist in GHz | nur innerhalb ähnlicher Generationen sinnvoll vergleichbar |
| Kerne | mehrere Recheneinheiten in einer CPU | helfen bei parallelisierbarer Arbeit |
| Threads | gleichzeitig planbare Ausführungsstränge | mehr Threads sind nicht automatisch mehr echte Kerne |
| Cache | sehr schneller Speicher in/nahe der CPU | reduziert langsame Zugriffe auf RAM |
| Leistungsaufnahme | Wärme und Strombedarf unter Last | beeinflusst Kühlung, Lautstärke, Netzteil und Notebook-Akkulaufzeit |

<Warnung titel="GHz ist kein Alleinurteil">
3,8 GHz ist nicht automatisch schneller als 3,4 GHz. Architektur, Generation,
Cache, Kerne, Speicheranbindung, Kühlung und die konkrete Aufgabe zählen mit.
Takt ist ein Kennwert, kein vollständiger Leistungsvergleich.
</Warnung>

### Kerne und Threads

Ein Kern kann echte Rechenarbeit ausführen. Mehrere Kerne helfen, wenn Arbeit aufgeteilt
werden kann: Videoexport, Kompilieren, virtuelle Maschinen oder viele gleichzeitige
Dienste profitieren eher als ein einzelner streng nacheinander laufender Ablauf.

Threads sind Befehlsfolgen, die das Betriebssystem plant und der CPU zur Ausführung
gibt. Viele moderne CPUs können mehr gleichzeitige Threads anbieten als physische
Kerne vorhanden sind; das macht einen einzelnen Ablauf aber nicht automatisch schneller.

## RAM: aktive Daten bereithalten

RAM ist flüchtiger Arbeitsspeicher. Er hält Daten und Programme bereit, die gerade
laufen. Beim Ausschalten ist der Inhalt weg; dauerhaft gespeichert wird auf SSD, HDD
oder einem anderen nichtflüchtigen Speicher.

| RAM-Frage | Bedeutung für die Auswahl |
|---|---|
| Reicht die Kapazität? | Viele Programme, große Dateien oder VMs brauchen mehr RAM. |
| Passt die DDR-Generation? | DDR4 und DDR5 sind nicht frei mischbar; Mainboard und CPU geben vor, was passt. |
| Wie ist der RAM bestückt? | Zwei passende Module können Dual-Channel ermöglichen; Handbuch beachten. |
| Braucht der Einsatz ECC-RAM? | Server und Workstations können von Fehlerkorrektur profitieren; CPU, Mainboard und Modul müssen ECC unterstützen. |
| Was passiert bei zu wenig RAM? | Das Betriebssystem lagert auf Massenspeicher aus; das System wird träge. |

RAM fühlt sich in der Praxis oft wie "Reaktionsfähigkeit" an: Browser mit vielen Tabs,
IDE, Datenbank, Teams, VM und Bildbearbeitung gleichzeitig brauchen Platz. Ist der RAM
voll, hilft eine schnellere CPU nur begrenzt, weil Daten ständig ausgelagert werden.

ECC ist kein anderes Wort für "mehr RAM". ECC-RAM speichert zusätzliche Prüfinformationen,
damit geeignete Systeme bestimmte Speicherfehler erkennen und korrigieren können. Für
normale Office-Clients ist meist Kapazität und Kompatibilität wichtiger; bei Servern,
Workstations und dauerhaft laufenden Systemen kann ECC ein begründetes Auswahlkriterium sein.

## Massenspeicher: dauerhaft speichern

Massenspeicher bleibt auch ohne Strom erhalten. Für Arbeitsplätze sind vor allem HDD,
SATA-SSD und NVMe-SSD wichtig.

| Speicherart | Prinzip | Stark bei | Schwach bei |
|---|---|---|---|
| HDD | rotierende magnetische Scheiben | viel Kapazität günstig bereitstellen | Zugriffszeit, Geräusch, Stöße |
| SATA-SSD | Flash-Speicher über SATA | schneller Alltagsbetrieb, leise, robust | SATA begrenzt den Durchsatz |
| NVMe-SSD | Flash-Speicher über PCIe/NVMe | sehr kurze Zugriffszeiten, hoher Durchsatz | braucht passenden M.2-/PCIe-Anschluss |

Eine SSD macht ein System oft spürbar schneller, weil Betriebssystem, Programme und
Dateien mit viel geringerer Wartezeit gelesen werden. Eine HDD ist trotzdem nicht
"falsch": Für Archive, große Mediendaten und Backup-Ziele kann Kapazität wichtiger
sein als maximale Reaktionszeit.

<Warnung titel="M.2 ist Form, NVMe ist Protokoll">
M.2 beschreibt einen Steckplatz beziehungsweise eine SSD-Bauform. NVMe beschreibt
das Kommunikationsprotokoll für nichtflüchtigen Speicher, häufig über PCIe. Eine
M.2-SSD kann je nach System SATA oder NVMe verwenden. Entscheidend ist, was
Mainboard, SSD und BIOS/UEFI tatsächlich unterstützen.
</Warnung>

## Zusammenspiel beim Programmstart

```text
1. Programm liegt dauerhaft auf SSD/HDD.
2. Betriebssystem lädt benötigte Teile in den RAM.
3. CPU holt Befehle und Daten aus RAM und Cache.
4. Ergebnisse landen wieder im RAM.
5. Dateien werden bei Bedarf dauerhaft auf SSD/HDD gespeichert.
```

Darum ist "mehr Speicher" keine eindeutige Aussage. Mehr RAM hilft bei gleichzeitig
aktiven Daten. Mehr SSD/HDD-Kapazität hilft bei dauerhaft gespeicherten Daten. Eine
schnellere CPU hilft bei Rechenarbeit. Ein unausgeglichenes System wird durch eine
einzige starke Komponente nicht automatisch gut.

## Auswahl nach Kundenwunsch

| Kundenwunsch | Hardwaregedanke |
|---|---|
| Office, Browser, Videokonferenz | solide CPU, genug RAM, SSD statt HDD für Reaktionsfähigkeit |
| Softwareentwicklung | ausreichend RAM, schnelle SSD, CPU mit guter Single- und Mehrkernleistung |
| Virtuelle Maschinen | viel RAM, mehrere Kerne, schnelle und große SSD |
| Bild-/Videobearbeitung | CPU-Leistung, viel RAM, schnelle SSD für Projektdateien, ggf. separate Archivplatte |
| Mobiles Arbeiten | Leistungsbedarf gegen Akkulaufzeit, Gewicht, Wärme und Lautstärke abwägen |
| Dateiarchiv/Backupziel | Kapazität, Redundanz und Backupstrategie wichtiger als Boot-Geschwindigkeit |

## Typische Fehler

| Fehler | Korrektur |
|---|---|
| RAM und SSD verwechseln | RAM ist flüchtig und aktiv; SSD/HDD ist dauerhaft. |
| Nur auf GHz schauen | Takt nur mit Architektur, Kernen, Cache und Aufgabe bewerten. |
| "Mehr Kerne = immer schneller" | Mehr Kerne helfen nur, wenn Arbeit parallel verteilt werden kann. |
| DDR4 und DDR5 mischen wollen | RAM-Generation muss zu Mainboard und CPU passen. |
| M.2 automatisch für NVMe halten | M.2 ist die Bauform; NVMe ist das schnelle Protokoll über PCIe. |
| SSD als Backup verstehen | Eine SSD ist ein Speicherort, aber kein Backup-Konzept. |

## Mini-Selbstcheck

| Frage | Saubere Antwort |
|---|---|
| Was verliert beim Ausschalten seinen Inhalt? | RAM. |
| Was speichert Dateien dauerhaft? | Massenspeicher, zum Beispiel SSD oder HDD. |
| Was führt Programmbefehle aus? | CPU. |
| Warum kann ein PC mit wenig RAM langsam werden? | Das Betriebssystem muss auf SSD/HDD auslagern. |
| Warum ist NVMe meist schneller als SATA-SSD? | NVMe ist für Flash über PCIe optimiert und umgeht SATA-Limitierungen. |
