## Worum geht's

Fast jeder normale Computer folgt bis heute einer Grundidee: Programm und Daten liegen
im Speicher, die *<Term id="cpu">CPU</Term>* holt nacheinander Befehle, dekodiert sie
und führt sie aus. Dieses Prinzip heißt Von-Neumann-Architektur oder Stored-Program-
Computer.

Das ist AP1-relevant, weil daran viele andere Themen hängen: Warum braucht ein Rechner
*<Term id="ram">RAM</Term>*? Warum ist Cache so wichtig? Warum kann eine schnelle CPU
trotzdem auf Speicher warten? Und warum sind Programme im Betrieb nicht nur "auf der
Festplatte", sondern als Befehle im Arbeitsspeicher?

## Was du danach kannst

- die Grundidee "Programm und Daten im gemeinsamen Speicher" erklären.
- die Hauptbestandteile CPU, Rechenwerk, Steuerwerk, Speicher, Bus und Ein-/Ausgabe zuordnen.
- den Fetch-Decode-Execute-Zyklus Schritt für Schritt beschreiben.
- den Von-Neumann-Flaschenhals erklären und Cache als Gegenmassnahme einordnen.
- Von-Neumann-Architektur grob von Harvard-Architektur unterscheiden.
- typische Prüfungsfallen vermeiden: RAM vs. Massenspeicher, CPU vs. ALU, Speicher vs. Cache.

<Analogie>
Stell dir eine Werkstatt vor. Im Regal liegen Arbeitsaufträge und Materialkarten
durcheinander im selben Fach. Der Meister holt immer den nächsten Auftrag, liest ihn,
gibt ihn an die passende Station weiter und legt das Ergebnis zurück. Das Regal ist der
Speicher, der Meister ist das Steuerwerk, die Rechenstation ist die ALU. Der Flur zwischen
Regal und Werkbank ist der Bus. Wenn der Flur eng ist, wartet selbst der schnellste Meister.
</Analogie>

## Faktenkern

| Baustein | Kurzform | Aufgabe |
|---|---|---|
| Steuerwerk | Control Unit | Befehle holen, dekodieren und den Ablauf steuern |
| Rechenwerk | ALU | Rechnen, vergleichen und logische Operationen ausführen |
| Register | Register | Sehr kleine, sehr schnelle Speicherplätze direkt in der CPU |
| Arbeitsspeicher | RAM | Aktive Programme und Daten während der Ausführung halten |
| Bus | Daten-/Adress-/Steuerbus | CPU, Speicher und Ein-/Ausgabe verbinden |
| Ein-/Ausgabe | I/O | Daten in den Rechner hinein oder aus ihm heraus bringen |

Die klassische Kurzform lautet:

```
CPU = Steuerwerk + Rechenwerk + Register
Von-Neumann-Idee = Programm und Daten teilen sich einen Speicherraum
```

Das passt zum *<Term id="eva-prinzip">EVA-Prinzip</Term>*:

| EVA-Schritt | Im Rechner |
|---|---|
| Eingabe | Tastatur, Maus, Netzwerk, Sensor, Datei |
| Verarbeitung | CPU führt Befehle aus und greift auf RAM zu |
| Ausgabe | Bildschirm, Drucker, Netzwerk, Datei |

## Die Kernidee: Stored Program

Vor programmierbaren Rechnern musste Verhalten oft durch Verdrahtung, Schalter oder
Steckfelder geändert werden. Die Von-Neumann-Idee macht Programme selbst zu Daten:
Ein Programm wird als Folge von Befehlen gespeichert, geladen und ausgeführt.

Das ist der große Sprung:

| Vorher gedacht | Von-Neumann-Prinzip |
|---|---|
| Neue Aufgabe braucht neue Verdrahtung oder Umstecken | Neues Programm in den Speicher laden |
| Daten und Ablauf sind technisch stark getrennt | Befehle und Daten liegen im gleichen Speicherraum |
| Maschine wirkt spezialisiert | Maschine wird allgemein programmierbar |

Darum kannst du auf derselben Hardware erst einen Browser, dann eine Tabellenkalkulation
und danach ein Spiel starten. Die Hardware bleibt gleich; die Befehle im Speicher ändern
sich.

## Fetch, Decode, Execute

Die CPU arbeitet nicht "magisch", sondern wiederholt einen Befehlszyklus. Moderne CPUs
sind intern viel komplizierter, aber für AP1 reicht dieses Modell:

<StepByStep titel="Der Von-Neumann-Zyklus">
  <Schritt nr={1} titel="Fetch - Befehl holen">
    Das Steuerwerk liest über den Bus den nächsten Maschinenbefehl aus dem RAM.
    Der Program Counter zeigt dabei auf die Adresse des nächsten Befehls.
  </Schritt>
  <Schritt nr={2} titel="Decode - Befehl verstehen">
    Die CPU dekodiert das Bitmuster: Ist es eine Addition, ein Vergleich, ein Sprung
    oder ein Speicherzugriff? Daraus entstehen Steuersignale für die beteiligten
    Bausteine.
  </Schritt>
  <Schritt nr={3} titel="Execute - ausführen">
    Das Rechenwerk führt die Operation aus. Bei `ADD` addiert die ALU Werte, bei
    `COMPARE` vergleicht sie, bei einem Sprung ändert das Steuerwerk den Program
    Counter.
  </Schritt>
  <Schritt nr={4} titel="Memory/Writeback - Ergebnis sichern">
    Das Ergebnis landet in einem Register oder im RAM. Danach zeigt der Program
    Counter auf den nächsten Befehl und der Zyklus beginnt von vorn.
  </Schritt>
  <Ergebnis>
    Der einfache Merksatz lautet: **holen, dekodieren, ausführen, Ergebnis sichern**.
    Genau dieses Muster steckt hinter jedem laufenden Programm.
  </Ergebnis>
</StepByStep>

## Mini-Beispiel: Addition im Rechner

Eine Aufgabe wie `a = b + c` sieht in einer Hochsprache harmlos aus. Die CPU sieht aber
kleine Maschinenbefehle:

```
LOAD b      // Wert b aus dem RAM holen
LOAD c      // Wert c aus dem RAM holen
ADD         // ALU addiert beide Werte
STORE a     // Ergebnis unter a speichern
```

Was daran wichtig ist:

- Werte müssen vom Speicher zur CPU.
- Die ALU rechnet, nicht der RAM.
- Ergebnisse müssen wieder in Register oder Speicher.
- Viele Befehle bedeuten viele Speicher- und Busbewegungen.

Genau hier entsteht später der Flaschenhals.

## Von-Neumann-Flaschenhals

Das klassische Problem: CPU und Speicher sind getrennt, aber die CPU braucht ständig
Befehle und Daten aus dem RAM. Wenn beide über denselben Weg müssen, begrenzt dieser
Weg die Geschwindigkeit.

```
CPU  <---- Bus ---->  RAM
      Befehle
      Daten
      Ergebnisse
```

Die CPU kann sehr schnell rechnen, wartet aber oft auf Daten. Deshalb fühlt sich eine
reine GHz-Zahl nie wie die ganze Wahrheit an. Entscheidend sind auch Cache, Speicher-
bandbreite, Latenz und Zugriffsmuster.

### Cache als Gegenmassnahme

Cache ist kleiner, aber deutlich schnellerer Speicher in oder nahe an der CPU. Er hält
Daten und Befehle bereit, die vermutlich gleich wieder gebraucht werden.

| Ebene | Typische Rolle | Prüfungsmerksatz |
|---|---|---|
| Register | Direkt in der CPU | am schnellsten, aber winzig |
| L1-Cache | Pro Kern, sehr nah | extrem schnell, sehr klein |
| L2-Cache | Pro Kern oder Kern-Gruppe | größer, etwas langsamer |
| L3-Cache | oft gemeinsam für mehrere Kerne | noch größer, nochmals langsamer |
| RAM | Arbeitsspeicher | viel größer, aber deutlich langsamer |
| SSD/HDD | Massenspeicher | dauerhaft, aber viel langsamer als RAM |

Cache löst den Flaschenhals nicht vollständig, aber er senkt die Wartezeit massiv,
wenn Programme auf nahe beieinanderliegende oder wiederholt genutzte Daten zugreifen.

## Von-Neumann vs. Harvard

In der Von-Neumann-Architektur teilen sich Programm und Daten denselben Speicherraum.
In einer Harvard-Architektur sind Programmspeicher und Datenspeicher getrennt.

| Merkmal | Von-Neumann | Harvard |
|---|---|---|
| Programmbefehle und Daten | gemeinsamer Speicherraum | getrennte Speicher |
| Zugriff | ein gemeinsamer Pfad kann bremsen | Befehle und Daten können parallel geholt werden |
| Typische Einordnung | allgemeine Rechner als Grundmodell | Mikrocontroller, DSPs, teils CPU-interne Caches |
| AP1-Kern | Stored Program + gemeinsamer Speicher | Abgrenzung kennen, nicht im Detail rechnen |

Wichtig: Moderne Rechner sind Mischformen. Nach außen nutzt die Software meist ein
Von-Neumann-Modell. Intern können getrennte Instruction- und Data-Caches wie eine
Harvard-nahe Optimierung wirken.

## Prüfungsnahe Einordnung

| Aussage | Bewertung |
|---|---|
| "Programme liegen bei der Ausführung im RAM." | richtig |
| "Programme sind dauerhaft auf SSD/HDD gespeichert." | ebenfalls richtig, aber anderer Zeitpunkt |
| "Die ALU steuert den Ablauf." | falsch, das macht das Steuerwerk |
| "Die ALU rechnet und vergleicht." | richtig |
| "Cache ist Massenspeicher." | falsch, Cache ist schneller Zwischenspeicher |
| "Von-Neumann bedeutet: Daten und Befehle können nie unterschieden werden." | falsch, sie liegen im gemeinsamen Speicherraum, haben aber unterschiedliche Bedeutung im Ablauf |

---

## Typische Fehler

- **RAM und Massenspeicher verwechseln.** SSD/HDD speichern Programme dauerhaft. Beim
  Ausführen werden Programmteile in den RAM geladen. Genau dort arbeitet die CPU mit
  ihnen.
- **CPU mit ALU gleichsetzen.** Die ALU ist nur das Rechenwerk. Zur CPU gehören auch
  Steuerwerk, Register und weitere interne Einheiten.
- **Steuerwerk als "denkende" Einheit sehen.** Das Steuerwerk bewertet keine Aufgabe
  fachlich. Es dekodiert Befehle und steuert Hardware-Signale.
- **Bus nur als Kabel vorstellen.** In der Architektur meint Bus allgemein den
  Kommunikationsweg samt Daten-, Adress- und Steuersignalen.
- **Cache als optionalen Speicherplatz verstehen.** Cache ist keine Ablage für Nutzer-
  Dateien, sondern ein automatischer Zwischenspeicher für Geschwindigkeit.
- **Von-Neumann als exakten Bauplan moderner CPUs lesen.** Moderne CPUs haben Pipelines,
  mehrere Kerne, Caches, Sprungvorhersage und parallele Einheiten. Das AP1-Modell bleibt
  trotzdem nützlich, weil es den Grundablauf erklärt.
- **Flaschenhals nur als "zu wenig RAM" deuten.** Der Von-Neumann-Flaschenhals meint den
  Datenverkehr zwischen CPU und Speicher, nicht einfach die RAM-Größe.

---

## Was hängen bleibt

Die Von-Neumann-Architektur erklärt, warum ein Computer allgemein programmierbar ist:
Befehle und Daten liegen im Speicher, die CPU arbeitet Befehle zyklisch ab, Ergebnisse
gehen zurück in Register oder Speicher. Die Stärke ist Flexibilität. Die Schwäche ist
der Weg zwischen CPU und Speicher, also der Von-Neumann-Flaschenhals.
